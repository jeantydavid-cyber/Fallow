# Fallow

Tracks the load going into a person's life and the recovery going in, week by
week, and shows the gap over months — so someone heading into autistic or ADHD
burnout notices it while there is still time to cancel something.

Not a mood tracker, not a habit tracker, not a diagnostic tool. Built from the
handoff package in `docs/handoff/`.

## Putting it on a phone

Pushing to the default branch builds and publishes the app to GitHub Pages
(`.github/workflows/deploy.yml`), at:

**https://jeantydavid-cyber.github.io/Fallow/**

Open that on the phone, then **Add to Home Screen** — Share → Add to Home
Screen on iOS Safari, ⋮ menu → Add to Home screen / Install app on Android
Chrome. It then opens full-screen from its own icon, with no browser chrome,
and works with no signal (a service worker caches the app's own files).

There is no app store build and no account. The data lives in the phone's
browser storage and never leaves it, which also means: clearing site data for
the domain erases it, and each device is separate. Settings → Export
everything writes the JSON backup, which imports on another device.

## Stack

- React + TypeScript + Vite, plain CSS custom properties (`src/styles/tokens.css` is the theme)
- Dexie / IndexedDB — everything stays on-device; no accounts, no server, no analytics
- Chart and icons are hand-built (divs and inline SVG; no chart or icon library)
- Nunito self-hosted from `public/fonts/`

## Running it

```sh
npm install
npm run dev        # dev server
npm test           # vitest — fixtures and model logic
npm run build      # type-check + production bundle
node scripts/screenshot.mjs  # milestone screenshot pass (needs `vite preview` running)
```

Dev-only fixture seeding for review: `/?fixture=drought`, `?fixture=sparse`,
`?fixture=busy-but-fine`, `?fixture=empty`, `?fixture=first-run`. The
`/styleguide` route shows every token (with runtime-computed contrast), every
component state, the chart's seven column states, and the full icon set.

## The load-bearing correctness rules

- **Unknown recovery is never zero.** A quick check-in leaves `recoveryKnown:
  false`; drought detection reads only known weeks; unknown weeks render as a
  dashed ghost, never a bare line. `sparse.json` must produce no warning.
- **Load alone is not the signal.** `busy-but-fine.json` must produce no
  warning; high load with intact recovery is stated plainly, never warned about.
- **Only one observation, ever.** Signals resolve in priority order
  (skill-loss drift → drought → category collapse → sustained deficit →
  neutral) and exactly one line renders on home.
- **Demands hang downward.** A heavy week never renders as a tall proud bar.
- **No notifications, ever.** The check-in is pulled, not pushed. The settings
  row about notifications is a statement, not a control.
- **No red, no orange, no `#000`/`#FFF`, no shadows, radii ≤16px.** Both
  themes' contrast is measured at runtime on `/styleguide`.
- **Every user-facing string lives in `src/copy.ts`** (the copy deck).
- **Fixed element ordering** on every screen; only presence varies.

All of the above are enforced by the tests in `src/tests/` or checked on the
styleguide; the three acceptance fixtures live in `src/fixtures/` and are
regenerated by `node scripts/emit-fixtures.mjs`.

## Calendar

`.ics` import is first-class (Settings → Import a calendar file). Events are
classified by taught rules (remembered after you answer once, inside the
check-in) plus heuristics; calendar-derived entries arrive as unconfirmed
guesses and the check-in is a review of them. Google / Microsoft OAuth PKCE
scaffolding is in `src/calendar/oauth.ts` and activates only when
`VITE_GOOGLE_CLIENT_ID` / `VITE_MS_CLIENT_ID` are configured at build time —
tokens would live in IndexedDB; calendar contents never leave the browser.

## Structure

```
src/
  copy.ts          the copy deck — every string in the app
  model/           types, week math, signals, observations, calibration, refit, lever, export
  db/              Dexie schema and repo
  calendar/        .ics parsing, classification + taught rules, OAuth PKCE scaffolding
  components/      Icon set, controls, chart
  screens/         home, check-in, lever, week detail, weights, onboarding,
                   low-capacity, settings, printable summary, styleguide
  fixtures/        drought / sparse / busy-but-fine acceptance fixtures
  tests/           vitest suites for the model and calendar layers
docs/handoff/      the design handoff this app is built from
```
